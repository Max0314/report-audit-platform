# 硬件研发部测试报告审核平台 - 扩展指南

## 一、平台扩展性设计概述

本平台采用模块化、配置驱动的设计理念，确保后续功能迭代、模块新增与版本升级无需重构核心代码。

### 1.1 扩展原则

- **配置与代码分离**：业务规则通过配置文件管理
- **模块独立封装**：各功能模块解耦，可独立升级
- **标准化接口**：统一 API 规范，便于对接新系统
- **组件化前端**：前端组件可复用，易于扩展

---

## 二、快速扩展指南

### 2.1 新增测试项目类别

**场景**：需要支持新的测试类别（如 EMC 测试）

**操作步骤**：

1. 编辑 `config/settings.yaml`
2. 在 `validation_rules.standard_test_items` 下新增类别：

```yaml
validation_rules:
  standard_test_items:
    EMC测试:              # 新增类别
      - 辐射发射
      - 传导发射
      - 静电放电
      - 射频辐射
```

3. 重启服务即可生效

---

### 2.2 新增测试值判定规则

**场景**：需要添加新的参数判定范围

**操作步骤**：

1. 编辑 `config/settings.yaml`
2. 在 `validation_rules.test_value_rules` 下新增规则：

```yaml
test_value_rules:
  新参数:                # 新增参数
    min: 0
    max: 100
    unit: "单位"
```

3. 系统将自动识别并应用新规则

---

### 2.3 新增日期格式支持

**场景**：需要支持更多日期格式

**操作步骤**：

1. 编辑 `config/settings.yaml`
2. 在 `validation_rules.date_formats` 下新增格式：

```yaml
date_formats:
  - "%Y-%m-%d"
  - "%Y/%m/%d"
  - "%d-%m-%Y"    # 新增格式
```

## 三、高级扩展

### 3.1 新增 AI 服务提供商

**场景**：需要切换到其他 AI 服务（如 OpenAI、Claude）

**操作步骤**：

1. 创建新的 AI 服务类 `app/services/ai_providers.py`：

```python
from app.services.ai_checker import AIChecker

class OpenAIChecker(AIChecker):
    """OpenAI 检查器"""

    def __init__(self):
        super().__init__()
        # 使用 OpenAI 配置
        self.config.base_url = "https://api.openai.com/v1"
        self.config.model = "gpt-4"
```

2. 在 `app/services/ai_checker.py` 中添加提供商切换逻辑

3. 在配置文件中指定提供商

---

### 3.2 新增统计指标

**场景**：需要添加新的统计指标（如百分位数）

**操作步骤**：

1. 编辑 `config/settings.yaml`：

```yaml
analysis:
  statistics:
    - max
    - min
    - mean
    - std
    - median
    - percentile_95    # 新增
    - percentile_99    # 新增
```

2. 在 `app/services/analysis_service.py` 中添加计算逻辑：

```python
def _calculate_percentile(self, values, percentile):
    """计算百分位数"""
    import numpy as np
    return float(np.percentile(values, percentile))
```

## 六、版本升级

### 6.1 升级流程

1. 备份现有配置和数据
2. 更新代码：`git pull` 或覆盖文件
3. 对比配置文件，合并自定义设置
4. 重启服务
5. 验证功能

### 6.2 配置迁移

升级时注意保留以下自定义内容：

- `config/settings.yaml` 中的自定义规则
- `.env` 中的 API 配置
- 上传的数据文件

---

## 七、最佳实践

### 7.1 配置管理

- 敏感信息（API Key）存于 `.env`
- 业务规则存于 `settings.yaml`
- 避免修改核心代码

### 7.2 模块开发

- 遵循现有代码风格
- 添加详细注释
- 编写单元测试

### 7.3 部署建议

- 使用 Docker 容器化部署
- 配置 Nginx 反向代理
- 定期备份数据目录
