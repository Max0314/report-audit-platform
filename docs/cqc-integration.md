# CQC 功能接入

## 部署边界

继续使用报告审核服务现有 Compose、OSS、门户会话鉴权和 NeoFlow AI 配置。
不增加容器、数据库、公网端口或 Nginx 配置；仅重建报告服务。
外部入口 `/neo_hardware/report-audit/` 302 到 `/review`，顶部四个功能入口，另有“返回硬件门户”按钮，返回 `/neo_hardware/neo/`。
本机发布地址仍为 `127.0.0.1:39023`，容器内 8000。
原 Excel 审核、聚合分析业务代码未替换为交付 ZIP 版本。
旧审核导出响应头的中文文件名改用 UTF-8 编码，修复原有的 Latin-1 编码异常；不改变审核规则。

## 处理与持久化

- 两个 CQC 上传接口返回 202 和任务 ID，前端轮询 `/api/v1/cqc/tasks/{id}`。
- 单份 PDF 限 50 MB、200 页；只支持可提取文字的 PDF。加密、损坏、扫描版及型号不一致给出明确错误。
- 规则解析使用独立的两个工作线程，每用户最多一个在途任务，整体最多两个。
- 原 PDF 先写 OSS，再解析；规则检查完成后直接归档 JSON 结果，不调用模型。
- 执行状态只是本进程临时缓存，最多 40 项，提交时淘汰已完成的过期项。无需新增持久任务表或本地数据库。
- 原文件在 `uploads/cqc/{task_id}/`；结果文件在 `results/cqc/{sha256(owner_key)}/{task_id}.json`，均位于现有服务 OSS 前缀内。
- 已归档结果可按当前页面的 `?task=` 链接在重启后恢复；正在解析的任务需重新提交，旧版本已解析的任务恢复规则结果，历史 AI 字段不再返回、展示或导出。
- 当前没有历史任务列表、自动重试队列和 OSS 自动删除策略；归档按服务现有数据保留制度处理。
- 导出 Excel 是从归档结果生成的派生文件，原文和结论均以文本单元格写入，禁用公式解释。
- 所有接口沿用门户 Cookie；写请求校验 CSRF；查看和导出均校验用户归属。API Key 仅在服务端使用。

## 分析范围

CQC单报告审核：四项基本字段、变更确认表、安全关键件清单、照片数量检查。
双报告：同型号校验、四项字段、关键件新旧完整字段、声明变更、照片像素变化。
不是全文或全部测试数据差异检查，也不提供 OCR 或 AI 图片理解。
照片配对采用标题和顺序、缩略图像素差异，不代表器件语义识别；应对照原图复核。

两个 CQC 功能不提供 AI 辅助分析。原有 Excel 智能审核继续使用 NeoFlow / `deepseek/deepseek-v4-pro`，配置和调用不变。

## 验证与发布

本地安装 `requirements-dev.txt` 后运行：

```bash
python -m unittest discover -s tests -v
python -m compileall -q app health_check.py
```

测试使用代码生成的合成 PDF，不包含客户数据。正式发布前进行浏览器交互验收；发布后用合成 PDF 验证两个 CQC 功能的规则、导出及权限隔离，并回归原 Excel 真实模型审核、聚合和导出。
真实 CQC 报告版式的识别准确率仍需业务人员以脱敏实际样本验收。

发布：保存当前镜像的回滚标签，本地提交并推送合并后，服务器 `git pull --ff-only`，运行 `bash scripts/deploy.sh`。
仅报告服务有短暂重启，不重启门户、AI BOM 或其他服务。
回滚：恢复旧版本提交和旧镜像标签，`bash scripts/deploy.sh --no-build`；不要删除 OSS 数据。
